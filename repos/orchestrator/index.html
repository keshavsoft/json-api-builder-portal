The Master Conductor

How the Orchestrator Works & Follows OpenAPI 3

The orchestrator brings together deterministic directory trees, AST route synthesis, and an industry-standard OpenAPI 3 contract into a runnable Hono HTTP backend.

1. Input File Hierarchy: The Specification Roots

Everything the generator creates is deterministically derived from test/v1/input/:

test/v1/input/ directory layout 
test/v1/input/
├── api.json                    # Endpoints, methods & strategies
├── data/
│   ├── clinics.json            # Mock DB records for clinics
│   └── players.json            # Mock DB for file-sync strategy
└── source-of-truth/
    ├── openapi.json            # OpenAPI 3.0.3 contract spec
    ├── tree.json               # Structural physical folder tree
    └── templates/
        └── routes.estree.json  # AST blueprint for route code
source-of-truth/openapi.json OpenAPI 3.0.3

The formal HTTP specification defining resources, parameters, response schemas, and HTTP status codes (200, 201, 404).

source-of-truth/tree.json Scaffold Schema

The deterministic physical folder tree. Controls where routes.js files are placed on disk without guesswork.

api.json Runtime Contract

Defines the root routing prefix (/api), server port, CRUD operations mapped to verbs, and file-sync strategies.

templates/routes.estree.json ESTree AST

Abstract Syntax Tree for JS route generation. Astring compiles this into clean JavaScript route files without regex or string concatenation.

2. Following OpenAPI 3: The Contract Architecture

How our architecture translates standard OpenAPI 3 schema objects directly into live endpoints

source-of-truth/openapi.json (OpenAPI 3.0.3) Specification 
{
  "openapi": "3.0.3",
  "info": {
    "title": "Clinics API",
    "version": "1.0.0"
  },
  "servers": [{ "url": "/api/v1" }],
  "paths": {
    "/clinics": {
      "get": {
        "operationId": "showAllClinics",
        "summary": "Show all clinics",
        "responses": {
          "200": {
            "description": "Success",
            "content": {
              "application/json": {
                "schema": {
                  "type": "array",
                  "items": { "$ref": "#/components/schemas/Clinic" }
                }
              }
            }
          }
        }
      }
    }
  },
  "components": {
    "schemas": {
      "Clinic": {
        "type": "object",
        "properties": {
          "id": { "type": "string" },
          "name": { "type": "string" }
        },
        "required": ["id", "name"]
      }
    }
  }
}
Generated: output/api/v1/clinics/routes.js Hono Output 
import { Hono } from "hono";
import { readFile, writeFile } from "node:fs/promises";
import path from "node:path";

const routes = new Hono();
const dataPath = path.resolve("../../../../data/clinics.json");

// Mapped directly from OpenAPI 3 GET /clinics:
routes.get("/", async (c) => {
  const rows = JSON.parse(await readFile(dataPath, "utf8"));
  return c.json(rows);
});

// Mapped directly from OpenAPI 3 POST /clinics:
routes.post("/", async (c) => {
  const body = await c.req.json();
  const rows = JSON.parse(await readFile(dataPath, "utf8"));
  rows.push(body);
  await writeFile(dataPath, JSON.stringify(rows, null, 2));
  return c.json(body, 201);
});

export default routes;

3. The Orchestration Pipeline

How build({ clientRoot }) conducts the 7 stages in deterministic sequence

Stage 0
validateConfiguration({ clientRoot })
Ensures api.json and tree.json exist and contain valid structures before anything touches disk.
Stage 1
createFolders({ clientRoot, outputRoot })
Walks tree.json to scaffold physical folders: output/api/v1/clinics, output/endpoints/fs, output/data.
Stage 2
createFiles({ clientRoot, outputRoot })
Touches placeholder route files and copies sample mock data (clinics.json, players.json).
Stage 3
insertContent({ clientRoot, outputRoot })
Reads routes.estree.json and compiles syntactically correct Hono route scaffolds using AST generator astring.
Stage 4
hookRoutes({ clientRoot, outputRoot })
Parses parent route modules with AST and mounts children: connects clinics/routes.js into v1/routes.js, and v1 into api/routes.js.
Stage 5
createApp({ clientRoot, outputRoot }) & hookAppStrategies()
Generates root app.js, binds Hono middleware, mounts routes, and wires server listener.
Stage 6
createEndpoints() & createFileSyncEndpoint()
Generates live CRUD logic for /clinics and registers the /fs/file-sync handler for disk syncing.
Stage 7
verifyGeneratedApp({ clientRoot, outputRoot })
Runs post-build verification, confirming all 7 generated files exist and pass JS syntax checking.
